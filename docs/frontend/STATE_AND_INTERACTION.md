# STATE_AND_INTERACTION.md

## 0. 通用状态视觉补充
- `loading` 使用统一加载壳层和骨架内容，避免只显示单个默认 spinner。
- `empty` 需要说明当前无数据的原因和下一步产生数据的方式。
- `error` 需要保留用户可读摘要、下一步建议、错误码和可复制 `request_id`。
- 通用状态只解释当前状态，不新增业务提交入口。

## 1. 通用状态模型
每个页面或模块必须至少处理以下四态：
- `loading`
- `success`
- `empty`
- `error`

禁止只实现 `loading + success` 两态。

## 2. 知识库页面
- 管理端知识库能力拆分为两个页面：
  - `/admin/kb`：列表、筛选、编辑、删除
  - `/admin/kb/create`：独立创建知识库
- 列表加载中：显示骨架或加载态。
- 创建中：提交按钮进入 `loading`，禁止重复点击。
- 更新中：编辑弹窗 `confirmLoading` 生效。
- 删除中：必须二次确认，删除后刷新列表并清理当前选中态。
- 创建页与编辑弹窗必须提供受控联网检索配置：`web_enabled` 使用开关控件，`web_search_topk` 使用数值输入，`allowed_web_prefixes` 与 `web_seed_urls` 使用多行文本框按“一行一个 URL”录入。
- 启用受控联网检索时，前端必须校验至少填写一个授权 URL 前缀；后端仍负责协议、内网地址、重定向越界和入口页归属等安全校验。

## 3. 文档入库页面
- 管理端文档能力拆分为两个页面：
  - `/admin/documents`：按知识库查看文档、当前任务和任务历史
  - `/admin/documents/upload`：独立上传文档，成功后返回管理页
- 上传中：禁止重复提交。
- 上传页支持文件上传与文本粘贴两种来源；文本粘贴必须先生成预览和分块，确认后才进入正式入库任务，不能绕过分块复核。
- 上传成功：自动进入任务跟踪。
- 任务轮询中：展示状态、阶段、进度信息。
- 任务结束：停止轮询并给出明确结果。
- 任务历史：必须可查看、取消、重试。
- 文档状态、历史任务结果、当前任务趋势应在同页可见，避免只能依赖表格逐行判断。

## 4. 问答页面
### 4.1 页面状态
- `loading`
- `success`
- `empty`
- `error`

### 4.2 发送状态
- `ask_idle`
- `ask_sending`
- `ask_streaming`
- `ask_stopping`
- `ask_failed`

### 4.3 业务状态
- `ask_answered`
- `ask_refused`

### 4.4 判定规则
- SSE `done.status=succeeded` 且 `refusal=false`：`ask_answered`
- SSE `done.status=succeeded` 且 `refusal=true`：`ask_refused`
- SSE `done.status=canceled`：回到 `ask_idle`
- HTTP 非 2xx 或 SSE `error`：`ask_failed`

## 5. 问答交互规则
- 用户通过知识库名称选择器切换知识库，不暴露 `kb_id` 输入框。
- 当前选中的知识库若在刷新后已不存在或已无权访问，问答页必须自动切换到首个仍可用的知识库，并清理失效会话上下文。
- 提交问题后，立即插入本地用户消息与助手占位消息。
- `token` 事件到达后增量拼接助手正文。
- `status` 事件到达后追加到当前助手消息的过程状态区，用于展示“分析问题、检索向量库、搜索授权网站、调用 LLM”等诊断信息；该状态区不参与答案正文复制，也不替代引用证据。
- `refusal` 事件属于本轮最终业务结果，必须覆盖流式生成期间的临时文本并清空临时引用，避免软拒答短暂呈现为普通回答。
- 助手正文按 Markdown 渲染；引用标记仍可点击定位证据。
- `citation` 事件到达后增量更新引用。
- `done` 事件到达后回填 `conversation_id / message_id / user_message_id / created_at`；登录态刷新服务端历史时，必须把本轮本地 `status` 过程状态迁移到同一 `message_id` 的历史消息上，避免回答完成后执行状态消失。
- 流式连接中断且已拿到 `run_id` 时，应查询 `GET /chat/runs/{run_id}`，若服务端已有会话消息，则以服务端历史替换本地占位消息。
- 重新生成同一用户问题时，只展示该用户消息下最新的助手回答；旧回答可保留在后端审计数据中，但不得在问答主线程重复占位。
- 如果 `citations` 非空，默认允许快速打开引用面板。
- 如果 `refusal=true`，显示建议块，不按接口失败处理。
- 如果 `refusal=true` 且存在 `next_steps`，优先渲染结构化建议卡片；`suggestions` 仅作为兼容文本补充。
- 拒答原因不得直接展示原始后端码，必须映射为中文说明；`request_id` 放在次级信息区并支持复制。
- `next_steps.action` 交互建议：
  - `search_keyword` / `rewrite_question` / `add_context`：优先回填到问答输入框，辅助用户继续追问
  - `check_official_source`：若 `value` 为 http/https 链接，则直接新开页跳转；否则管理员可跳转文档管理页，普通用户给出查看官网或联系管理员的提示
  - `verify_kb_scope`：管理员可跳转文档管理页；普通用户给出查看官网或联系管理员的提示
- 历史会话回放时，若助手消息已持久化 `next_steps`，渲染规则与当次问答完成态保持一致。
- 历史会话中的助手消息若已持久化 `request_id`，应沿用与问答完成态一致的排障展示方式。
- 历史会话中的助手消息若已持久化 `suggestions`，也应与当次拒答态一致展示，不得静默丢弃。
- 会话运营台中的历史拒答建议应保持可操作：官网类建议直接打开，文本类建议优先复制，不额外引入新的提问输入框。
- 助手消息正文区域必须保留文本选择与复制能力，不得绑定整条消息点击打开证据弹窗。
- 证据弹窗只通过引用编号、“查看引用/查看证据详情”图标按钮或证据相关明确入口打开；消息操作区统一使用小尺寸图标按钮，避免把工具入口误读为回答正文；消息内按钮、链接、反馈入口、图片缩略图和图片预览操作不得连带触发证据弹窗。
- 会话运营台也必须支持点击助手历史消息打开证据详情弹窗，弹窗内展示 `request_id`、`timing` 与引用证据；引用编号仍可在消息内高亮对应证据卡。
- 证据弹窗支持按钮关闭与键盘关闭。
- 证据卡片若带可信 `source_uri`，应提供“官方来源”链接，避免用户只能停留在片段级证据；演示页、本地路径和占位地址不得显示为官方来源。
- 证据卡片若带 `assets[]`，回答正文下方集中渲染去重后的图片缩略图；点击缩略图只触发图片预览，不应连带打开证据详情弹窗。证据卡片仍提供“查看原图”入口，通过鉴权接口拉取 blob 后弹窗预览。
- 输入区必须始终可见，不被消息流挤出页面。
- 消息列表底部留白必须随输入区和拒答建议快捷按钮高度动态调整；拒答卡片、建议区或图片证据渲染导致高度变化后，仍应自动滚动到本轮消息底部。
- 输入区上方允许提供快捷问题填充按钮，但只能回填到现有输入框，不新增第二套提问入口。
- 问答页顶部允许展示紧凑的上下文摘要卡，只能表达当前知识库、会话状态、引用概况，不得挤占消息主路径。

## 6. 会话列表规则
- 会话侧栏支持按知识库和关键字过滤。
- 会话侧栏只展示当前登录用户自己的会话，管理员在问答视角也不能混入其他用户会话。
- 允许新建、重命名、删除会话。
- 切换会话时加载最近消息页。
- 当前选中的会话若在刷新后不存在，必须自动回退到当前知识库下首个仍可用的会话；若列表为空则清空线程区。
- 当前选中的会话若返回“无权访问该会话”，必须按失效会话清理，并保留用户刚输入的问题文本。
- 支持“加载更早消息”。
- 加载失败时不清空侧栏会话列表。
- 侧栏品牌区允许补充当前知识库、会话模式和上下文状态等低频摘要，帮助演示时快速说明当前工作上下文。
- 问答端侧栏应与管理端侧栏保持同一三段式比例：品牌区、会话/导航区、身份区，避免两个入口视觉割裂。

## 7. 反馈规则
- 反馈入口只对助手消息展示。
- 已提交反馈的消息应进入不可重复提交状态。
- 提交失败时允许重试。

## 8. 用户管理页面
- 用户管理仅 `admin` 可见；`manager` 虽可进入管理端，但不得看到用户管理导航，也不得直接访问 `/admin/users` 与 `/admin/users/create`。
- 管理端用户能力拆分为两个页面：
  - `/admin/users`：用户列表、状态编辑、角色配置、知识库授权
  - `/admin/users/create`：独立创建用户
- 创建用户成功后刷新列表并保留默认角色 `user`。
- 编辑用户支持修改状态、角色，可选重置密码。
- 权限弹窗支持：
  - 查看已有权限
  - 新增或更新单条权限
  - 撤销单条权限
  - 批量覆盖权限列表

## 9. 评测中心页面
- 管理端评测能力拆分为两个页面：
  - `/admin/eval`：发起评测、查询结果、查看指标
  - `/admin/eval/create`：独立设计评测集
- 创建评测集后，应自动进入最近评测集缓存。
- 创建评测样本必须录入标准证据文档名称，避免生成无法计算 Recall@K 与 MRR 的空标准样本。
- 发起评测必须选择评测集和知识库。
- 标准文档与目标知识库不匹配时，运行失败并显示可追踪错误，不展示误导性的零分结果。
- 查询结果时同时展示：
  - 指标卡
  - 图表
  - 汇总指标表格
  - 逐题命中、排名、耗时与候选摘要表格

## 10. 队列监控页面
- 队列统计默认 10 秒自动刷新。
- 危险操作必须二次确认。
- 结构分布、阶段对比、总量趋势、风险趋势应与指标卡同时存在。
- 队列统计请求成功但所有计数均为 `0` 时，表示当前没有待处理或历史登记任务，属于健康的成功态；页面仍需展示零值指标、运行时诊断和刷新入口，不得退化为通用空态。

## 11. 认证状态
- `auth_loading`
- `authenticated`
- `anonymous`

要求：
- 登录成功后跳转到 `next` 或默认首页。
- token 过期时自动刷新一次。
- 刷新失败时回到匿名态。

## 12. 近期补充
- 问答布局补充（2026-03 第五轮）：
  - 用户消息右侧，助手消息左侧。
  - 输入区固定在底部。
  - 移动端允许退化为单列消息流。
- 问答摘要补充（2026-03 第六轮）：

  - 摘要图仅基于当前会话现有消息，不引入独立接口。
- 管理端页面拆分补充（2026-03 第七轮）：
  - `/admin/users` 与 `/admin/users/create` 拆分

  - `/admin/eval` 与 `/admin/eval/create` 拆分

## 13. 认证路由补充（2026-04 浏览器检查轮）
- 受保护路由必须在 `auth_loading` 完成前保持统一加载壳层，不得提前重定向到登录页。
- 管理端子路由需要保留用户直接访问的目标路径；未登录时跳转登录页必须携带 `next`，登录成功后回到原目标。
- 已登录用户访问 `/login` 时可以按角色回到默认工作台，但不得影响直接打开 `/admin/users`、`/admin/documents` 等子页面。
- 路由加载态必须使用项目统一 `route-loading` 壳层，避免组件库开发期警告暴露在控制台。

## 14. 响应式交互补充（2026-05）
- 问答页桌面端保持会话侧栏常驻；`900px` 以下会话列表和身份区默认收起，只保留知识库选择、搜索与会话操作，保证消息阅读和输入优先。
- 问答页消息列表必须是主滚动区，输入区始终固定在消息卡片底部；移动端不得出现输入区被消息流挤出视口的问题。
- 管理端工具条在窄屏纵向堆叠后，搜索、筛选、刷新、创建等操作仍必须保持原有业务语义，不得因为隐藏文字而丢失 `aria-label` 或 `Tooltip`。
- 宽表格在中小屏只允许表格内部横向滚动；页面外层不能产生横向滚动条，避免演示时整个工作台左右漂移。
