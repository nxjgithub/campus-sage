## 1. 目标
CampusSage 前端用于完成以下闭环：
- 知识库治理
- 文档上传与入库
- 证据问答
- 引用查看
- 反馈回收
- 会话回放
- 监控与评测

## 2. 角色与入口
- 管理员端：`/admin/*`
- 用户端：`/app/*`
- 登录页：`/login`

管理员负责治理、入库、评测、监控、用户与权限。
用户负责提问、查看引用、提交反馈、管理会话。

## 4. 前后端契约原则
- 以前后端文档与 OpenAPI 为准，不伪造字段。
- `refusal=true` 是正常业务结果，不按失败处理。
- 所有错误提示必须可关联 `request_id`。
- 所有引用展示必须包含：
  - `doc_name`
  - `page` 或 `section_path`
  - `snippet`
  - 若存在图片资产，展示“查看原图”入口

## 5. 当前前端能力
### 管理端
- 知识库列表维护、独立创建、编辑、删除、策略配置
- 用户列表维护、独立创建、状态编辑、角色配置、知识库授权
- 文档列表维护、暂存上传、版式化解析预览、图片资产预览、分块启停、任务查看、取消、重试、重建索引
- 评测运行、评测结果查看、独立评测集创建，并优先使用服务端评测集与运行列表
- 队列监控、失败任务迁移、运行时诊断摘要

### 用户端
- 选择知识库提问
- 流式回答，助手聊天框按 Markdown 渲染
- 引用弹窗，支持在回答中直接渲染图片证据并打开原图
- 拒答建议
- 会话列表、重命名、删除
- 反馈、重试、改写后重发
- 主流 AI Chat 式单列对话流、底部聚焦输入框与空态示例问题

## 6. 近期界面方向
- 门户壳层统一为左侧侧栏工作台。
- 管理端页面统一为紧凑页头 + 双栏工作台 + 图表摘要。
- 复合型管理页优先拆成“管理页 + 独立创建或上传页”，避免录入表单和结果表格互相挤压。
- 用户端问答页统一为聊天式布局，摘要图只做轻量补充。
- 用户端问答页采用“轻会话侧栏 + 中央消息流 + 底部输入框”的主流 AI Chat 结构，首屏只保留必要的知识库范围、证据约束和示例问题。
- 用户端问答页作为主入口时直接加载聊天工作台；登录页、门户布局和管理端页面保持懒加载，降低首屏包体和 HTML 预加载压力。
- 全部页面按 `1280 / 1024 / 768` 三组断点检查：管理端表格只在表格容器内部横向滚动，问答端中屏以下收起会话列表并保持输入区可见。

## 7. 完成标准
- 每个页面必须具备 `loading / success / empty / error` 四态。
- 高风险操作必须二次确认。
- 文档、代码、行为必须同步。
- 图表只增强判断，不替代表格和精确数据。
